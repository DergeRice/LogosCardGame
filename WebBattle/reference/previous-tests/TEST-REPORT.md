- 현재 원본 문법을 연결한 **브라우저 테스트 4개 모두 통과** (2.1분): 90초 사람 경기/14:14 무승부/새로고침/재대결/30초 이탈 유예, 모바일 90초 AI 경기/결과/재대결, 자동 게스트·원본 카드, 부채꼴·필드 이동·부분 판정. 최종 TypeScript strict 빌드와 컴파일된 운영 서버 smoke도 통과했습니다.

## WebSocket 통합 테스트 세부

실제 `ws` 소켓을 사용하는 독립 클라이언트 2~3개를 실행했습니다. 클라이언트 점수·승리 주장은 서버에서 사용하지 않는지 확인했습니다.

- 존재하지 않는 방, 가득 찬 방, 진행 중 방 참가 거절.
- 서버 발급 6자리 방번호, 공통 경기 ID·마감 시간·동일 시작 덱 구성.
- 상대 카드 ID 및 상대 세션 토큰이 수신 상태에 없는지 검사.
- 두 클라이언트 동시 제출이 각자 14점으로 반영.
- 동일 requestId 중복, 이전 손패 버전, 이전 경기 메시지 거절.
- 위조 카드 ID, 같은 카드 중복, 틀린 품사 배열 거절 및 점수 불변.
- 연결 단절 → 동일 토큰 재연결 → 기존 점수/방 유지.
- 결과 → 양쪽 재대결 → 새 경기 ID/0점/새 손패.
- 재대결 양쪽 동의 중 한 명 단절 → 재접속으로 자동 경기 시작 (멈춤 방지 회귀).
- 유예 초과 이탈, 대기실 만료 정리, 잘못된 JSON, 연타 제한.
- AI의 실제 유효 제출 득점, 재대결, 문법 조합이 없는 손패 처리.
- 시작 손패 순서를 회전시킨 10가지 배열 × 3난이도에서 유효 수 발견.

## 정상 플레이와 가속 검증 구분

**브라우저 검증:** 기본 90초 경기와 기본 30초 유예를 그대로 사용했습니다. 사람/AI의 카드를 UI로 선택하고 서버에 제출했습니다. 점수나 승패를 직접 바꾸지 않았습니다.

**통합 테스트:** 대기실 만료 0.4초, 경기 1.2/4/5초, 유예 0.5/0.6/1초 등 서버 생성자 옵션으로 시간만 단축합니다. 강제 점수·승패 변경은 없습니다.

**운영 smoke:** 컴파일된 서버를 별도 포트 3002에 실제 실행하여 연결/경기 진입을 확인합니다. 전체 90초 플레이 검증은 위의 브라우저 테스트가 담당합니다.

## 발견 후 수정한 문제

1. 초기 브라우저 offline 에뮬레이션이 기존 WebSocket을 닫지 않아 이탈 검사가 실패했습니다. 실제 browser context 종료로 바꾸어 기본 유예 종료를 확인했습니다.
2. 200ms 타이머 갱신 때 내부 카드 컴포넌트가 remount되어 드래그가 끊길 수 있었습니다. 안정적인 key를 가진 동일 DOM 구조로 바꾸고 실제 드래그 제출을 검증했습니다.
3. AI가 무효 순열에 탐색 예산을 소진해 유효한 초기 손패에서도 첫 수를 놓쳤습니다. 짧은 문형부터 후보를 만드는 방식으로 수정하고 손패 순서 회귀 테스트를 추가했습니다.
4. 양쪽 재대결 동의 시 한 명이 끊겨 있으면 버튼이 모두 잠길 수 있었습니다. 복귀 시 동의/연결 상태를 다시 확인하여 시작하도록 수정했습니다.

초기 오프라인 테스트 때 개발용 Vite WebSocket 프록시에 `ECONNABORTED` 로그가 발생했습니다. 의도적 연결 차단 시점의 로그이며 서버 프로세스는 계속 health 응답했습니다. 이를 오류가 전혀 없었던 실행으로 보고하지 않습니다. 최종 브라우저 시나리오에서는 uncaught pageerror가 없습니다.

## 한계

- 모바일은 실제 휴대폰이 아닌 Chromium 터치/뷰포트 에뮬레이션입니다. Safari/iOS/Firefox는 아직 검증하지 않았습니다.
- Netlify/Render 실제 공개 URL, 무료 서버 cold start, 인터넷 지연, 대규모 동시 접속 부하 검증은 아직 하지 않았습니다.
- 후속 제공된 C# 문법 판정기는 실제 컴파일 대조를 완료했습니다. Unity Editor 씬 및 원래 네트워크 대전 전체를 실행한 것은 아닙니다.
- 스크린샷은 `docs/screenshots/`, 최근 Playwright HTML 리포트는 `playwright-report/index.html`입니다. 다음 테스트 실행은 이전 리포트를 덮어씁니다.
