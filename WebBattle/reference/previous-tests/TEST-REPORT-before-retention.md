## 실제 통신 검증

`tests/realtime.test.ts`는 실제 HTTP 서버를 임의 포트에 띄우고 독립 WebSocket 클라이언트들을 연결합니다.

- 4명이 같은 방에 자동 합류, 예약 AI 제거, 5번째 참가자는 다른 방으로 분리.
- 공용 120장 덱에서 각자 5장, 총 20개 고유 ID. 전원 추가 지급 후 덱 100→96, 손패 5→6.
- 다른 사람 카드 ID·품사·토큰, 덱 순서, 사용 카드 목록이 송신 상태에 포함되지 않음.
- 서버가 자연스럽게 나눠준 손패만 이용해 유효 조합을 제출. 동시 요청/중복 제출을 거쳐 1고 2배 → 2고 3배 → 3고 4배 → 스톱 종료.
- 다른 사람의 고 주도권 사용 차단, 같은 choice 재전송으로 배율 중복 증가 방지.
- 인정 카드만 소모, 즉시 보충 없음. 최종 보상·레이팅 산식, 정산 중복 방지, 전원 동의 재대결.
- 게스트 토큰 재접속 시 동일 손패와 경기 복귀. 이탈 유예 만료, 기권 정산, 결과방 만료.
- 실제 AI 행동으로 득점·종료·재대결. 위조 카드/잘못된 JSON/과도한 요청 처리.

통합 테스트에서는 **시간 간격만 단축**했습니다. 덱·손패·점수·승패를 강제 변경하지 않았습니다.

## 실제 브라우저 검증

`tests/browser/quick.spec.ts`는 서버 기본 시간(6초 매칭, 10초 지급, 90초 경기)을 사용합니다.

1. 독립 PC/모바일 context 두 개: 시작 화면의 주 버튼 1개, 자동 게스트, 빠른 매칭, VS, 초기 5장, 10초 추가 지급. 부채꼴 카드의 실제 노출 지점을 클릭/터치하고 필드 이동·되돌리기 확인. 정상 문법 제출로 양쪽 점수 동기화, 스톱 정산, 레이팅 표시, 재대결, 새로고침 후 동일 손패 복귀.
2. 모바일 AI: 빠른시작만으로 AI 자동 매칭, 자연 진행 결과, 재대결. 최대 기본 90초를 실제로 기다림.
3. 독립 브라우저 4개: 같은 테이블, 4인 프로필/초기 카드, 한 명의 나가기와 나머지 결과 동기화, 모바일 가로 넘침 검사.

브라우저 시나리오는 실제 손패를 읽고 유효한 조합을 클릭할 뿐, 서버 상태나 점수를 바꾸지 않습니다. 모바일은 390×844 터치 에뮬레이션이며 실제 휴대폰 하드웨어 검증은 아닙니다.
