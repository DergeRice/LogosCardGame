# v0.9.82 결과 화면

## 동작
- 승리 / 패배 제목, 하단 작은 회색 ‘이름의 승리!’. 실제 동점은 무승부.
- 내 프로필·나의 결과·기존 포인트/골드 상세 표·결과 예문을 제거. 내 리그와 레이팅만 정수로 카운트업한다. 패배는 실제 하락 값으로 내려가며, 첫 3판 배치 규칙도 유지한다.
- 화면 탭 → 상단 재화 HUD 등장 → PixiJS 골드 폭발/이동 → 모두 도착한 뒤 실제 골드 잔액 카운트업과 효과음. 효과음은 기존 음량 설정을 따른다.
- 연출은 서버가 이미 정산한 coinReward/coins를 표시할 뿐이다. 결과 재전송·연타로 보상 지급 메시지를 만들지 않는다. 렌더러 오류/동작 줄이기에서도 진행을 잠그지 않는다.
- 주요 버튼 2개: 다시 하기 / 시작화면으로. 친구 추가는 함께한 플레이어 목록에 유지한다.
- 직접 만든 방은 방번호/방장/참가자를 유지해 전원 동의 후 재대결. 혼자 남은 방, 덱 소진 종료도 새 덱으로 재개 가능하다.
- 빠른 시작은 서버 retryMatch가 기존 결과 방을 떠나 새 큐로 연결한다. 현재 경기 ID와 result 상태를 검사해 이전 경기 요청·연타를 거절한다.

## 검증
- npm test: 186/186. 재시도 테스트 4개 추가(직접 게임 상태 검사 3개 + 실제 2 WebSocket 통신 1개). 짧은 durationMs로 자연 시간 종료를 사용한 테스트이며 점수 강제 설정으로 종료하지 않는다.
- TypeScript / 운영 빌드 / Cloudflare 타입 검사 통과.
- Chromium·WebKit의 PC 1366×900, 모바일 가로 844×390(visualViewport 높이330, 위20) 결과 화면: 제목·레이팅·골드 도착 전후 잔액·주요 버튼·재전송·패배·배치 표시·페이지 스크롤 검사. 캡처 직접 확인. 실물 Android/iPhone 테스트와 구분한다.
- 운영 Cloudflare: 실제 독립 WebSocket 3개, quick → 매칭 → 카드 배분/시작 → 한 명 정상 항복 → 다른 두 명 결과 → retryMatch → 새 방 같은 큐. 이전 요청 거절, 잔액 유지. 직접 만든 방의 시작 → 상대 항복 → 같은 코드 재시작도 확인. 강제 점수/승패 변경 없음.
- 기존 battle-recovery의 종료 시 카드 대화창 닫기 검사도 새 제목으로 갱신.
- 기존 SFX 브라우저 테스트는 개발 소스 /src/gameSfx.ts를 직접 import하므로 Vite preview에서 실행하면 실패한다. 이번 결과 화면 검사와 구분하며 운영 전체 브라우저 테스트가 모두 통과했다고 주장하지 않는다. 개발 서버에서 다시 실행해 Chromium SFX 검사는 통과했다. Windows WebKit은 Web Audio가 없어 해당 오디오 테스트가 skip된다. 결과 관련 브라우저 검사는 6개 통과, SFX 검사는 1개 통과/1개 skip이다.
