# v0.9.78 — 고 재제출 / 점수 계산 / 예문 2초

- 서버가 한 경기에서 이미 득점한 전체 카드 ID 순서를 기록합니다. 같은 배열을 새 요청 ID로 다시 보내거나, 손으로 회수했다가 그대로 올려도 재제출을 거절합니다. 클라이언트도 해당 배열에서는 제출 버튼을 비활성화합니다. 같은 요청 ID의 통신 재전송은 기존 ACK 처리로 유지합니다. 자신의 기록만 클라이언트에 전송하며 다음 경기에서 초기화합니다.
- 점수 원장에 고 보너스 전 기본 점수와 실제 반영한 점수를 분리합니다. 겹치는 카드의 기본 점수가 기존보다 높아야 추가 득점합니다. 순서만 바꿔 기본 점수가 같은 조합에는 +3/+6/×2 혜택만으로 추가 득점하지 않습니다. 자기 다음 고 권한은 기본 누적 점수가 본인이 고를 선택한 시점의 기본 점수를 넘었는지도 확인합니다. 상대 추월 규칙은 기존 표시 점수 비교를 유지합니다.
- Judgment.points는 문장 전체 계산값으로 유지하고, awardedPoints가 중복 계산분을 뺀 실제 추가 득점입니다. 이전처럼 points를 차액으로 덮어쓰지 않아 3고에서 문장 점수 연출이 ‘서버 확정 값 0’ 하나로 사라지지 않습니다. 서버 점수판은 awardedPoints만 더합니다.
- 예문은 음성 사용 여부·로딩·실패·재생 시간과 무관하게 표시 후 2초에 닫습니다. 누르거나 Escape로 먼저 닫는 동작도 유지합니다. 패널 자동 닫힘이 음성을 중단하지 않습니다.

## 검증

- 단위/회귀 테스트 177개 통과. 제보 재현 fixture에서 최초 26점 → 1고 → 동일 문장 거절 → 기본값 26인 순서 변경은 추가 득점 0 → 기본값 30/34로 2고·3고 → 기본값 38의 문장 전체 76점/실제 추가 36점을 확인했습니다. 점수 원장·재제출 기록의 저장 복원도 검사했습니다.
- 위 고 단계 검사는 제어된 카드 fixture이며 정상 무작위 덱 실전 완료로 보고하지 않습니다.
- 관련 Playwright 검사 8개 통과, Windows WebKit 음성 검사 2개 제외. 브라우저에서 PC·모바일 가로 및 작은 visualViewport의 점수 연출, 정수 점수 증가, 3고 후 동일 문장 제출 비활성화, 예문 2초 자동 닫힘을 검사합니다. Windows WebKit은 Web Audio 미지원으로 실제 음성 재생 검사에서 제외하고, 2초 닫힘과 화면 동작은 검사합니다. 실물 휴대폰 검증은 하지 않았습니다.
- 음원 파일과 문법 허용 조합, 상자 확률은 변경하지 않았습니다.

- 전체 브라우저 스위트 통과를 주장하지 않습니다. 별도 실행한 기존 score-animation.spec.ts는 이미 제거된 pixi-embers 요소와 과거 인정 구간·배치·말풍선 지속시간을 기대해 실패했습니다. 이 파일은 변경하지 않았으며 이번 제보용 threego-score.spec.ts로 현재 계산·애니메이션·중복 제출을 검사했습니다.
