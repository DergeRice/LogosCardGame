# v0.9.84 카드 채움 로딩

- 기존 PixiLoading의 loading.png 머리 움직임과 loading-under.png 화면을 제거했다.
- PixiJS v8 Graphics 카드 마스크를 아래에서 위로 늘려 실제 완료 진행률에 맞춰 채운다. 머리 아이콘을 리소스 준비 목록에서도 제외했다. 문자0~100%와 접근 가능한 progressbar를 함께 표시한다.
- 카드 얼굴 완료 건수 + UI 아트 완료 건수 + 프로필 묶음 완료1건을 합산한다. 프로필9개 개별파일이나 네트워크 바이트 비율이라고 주장하지 않는다. 예문 음성은 주문형 경로이므로 이 백분율에 포함하지 않는다.
- 이미지 다운로드뿐 아니라 decode까지 마친 항목을 완료로 센다. 카드 또는 UI 필수 이미지 실패 시99% 이하와 재시도를 표시하며100%로 넘어가지 않는다.
- 기존 GameEntry에서 미리 준비했을 때도 단일 공유 Promise와 구독자로 현재 진도를 받는다. 렌더 완료 전에는99% 이하, 전체 성공 후100%를500ms 표시한 뒤 홈으로 이동한다.
- 모바일 캔버스는 부모 크기에 맞춰 표시하도록 Pixi inline 크기를 덮어써 숫자/문구를 가리지 않게 했다. reduced-motion에서는 진도 즉시 반영, WebGL 불가/컨텍스트 유실에서는 동일 진도의 정적 CSS 대체 카드. 비활성 탭 ticker중지, 완료 후 정지, 언마운트 renderer해제. 모바일24FPS/제한 DPR, PC30FPS.

## 검사
- npm run build / 최종 tsc와 Vite빌드 통과.
- Chromium·WebKit PC/모바일가로 화면 총6검사 통과. 모바일844×390, visualViewport330/top20으로 시스템 UI 영역 모사.
- 실제 카드 요청을 지연시키고 UI 이미지1개를 잠시 보류하여 진도 상승/100%미도달/홈미진입을 확인. 보류 해제 후100% 표시와 홈진입, 값의 단조 증가를 확인했다. 필수 이미지 실패 시 재시도와100%미표시도 확인했다.
- 실제 파일을 내려받아 디코딩하며 진행률 값을 강제 설정하지 않았다. 서버 메시지만 테스트 fixture를 사용한다. 카드 그림과 퍼센트의 영역이 겹치지 않는지 검사하고 캡처를 직접 확인했다.
- WebKit에서는 미완료 이미지 요청을 보류한 상태의 screenshot이 페이지load를 기다리므로, 해당 상태는 DOM/수치로 검사하고100% 이후의 캡처를 확인했다.
- 실물 Android/iPhone 검증은 아니다. 서버/경기 규칙과 음원은 수정하지 않아 Cloudflare 재배포는 필요 없다.
- Git web-battle푸시 후 Netlify의 같은HEAD ready와 운영주소 로딩 검사를 확인한 뒤 완료 보고한다.
