# v0.9.64: I can work near our friends.

사용자 제보 문장 `I can work near our friends.`의 기존 R2 키 `14ec0701df5835da2005.mp3`와 현재 생성기 기본형 `I can work near our friend.`의 `f1e79f36c38facf2fe70.mp3`는 모두 HTTP 404였다.

운영 관리자 로그도 확인했다. 같은 방·플레이어·카드 6장 조합에서 `AUDIO_FAILURE`, `reason: missing:404:running`, 클라이언트/서버 v0.9.63이 두 번 기록됐다. 앞선 제출의 카드 종류는 pronoun, modal, verb, preposition, possessive, count였다. 오디오 컨텍스트는 running이므로 이 사례의 직접 원인은 자동재생 차단이 아니라 파일 누락이다. 기존 기록에는 문장 문자열과 파일명이 없어 제출 카드와 대조했다. 이후 실패 기록에는 정확한 문장과 파일명도 포함하고 warn으로 저장한다.

24,155개 기존 음원 목록을 다시 검증하는 것만으로는 목록 밖의 생성 문장 누락을 찾을 수 없었다. 전치사 뒤에 관사/소유격과 명사가 오는 이 계열을 대상으로 실제 판정기가 전체 카드를 인정하는 문장을 새로 생성했다. 제보한 복수형까지 **114개 전체 문장 MP3**를 동일 Kokoro `af_heart` 목소리로 오프라인 생성하고 로컬 manifest에 추가했다. 약 2.05MB이며 유료 API 호출은 없다. 단어를 이어 붙이거나 비슷한 다른 문장으로 바꾸지 않는다. 모든 가능한 문장 조합을 완성했다는 의미는 아니다.

배포 검증 중 새 운영 로그에 같은 404가 추가로 남았다. 직전 제출 카드로 복원한 `Does the teacher give them the book very well?`, `Does the teacher need the book very well?`도 보충해 이번 보충 음원은 최종 **116개**, 로컬 manifest는 총 **663개**다. 해당 요청의 클라이언트 버전은 여전히 v0.9.63이었으며, 새 목록과 표시를 사용하려면 새로고침이 필요하다.

음원이 없을 때의 문구를 “이 문장 음성 준비 중”에서 “이 문장 음원 없음 · 다시 확인”으로 바꿨다. 진행 중인 다운로드와 미등록 파일을 구분하고, 디코더가 응답하지 않는 경우에도 5초 뒤 재시도 가능한 timeout 상태로 바꾼다. `/audio-check`에 제보한 두 문장을 추가했다.

페이지를 오래 열어 둔 상태에서 새 음원이 배포되어도 반영되도록, 404 응답 시 최신 manifest를 한 번 다시 가져오고 경로가 바뀌었으면 그 파일로 재시도한다. 기존 목록이 비어 있고 R2는 404인 상태에서 새 로컬 음원을 발견하여 끝까지 재생하는 회귀 검사를 포함한다.

사용자의 명시적 요청에 따라 `/admin` 로그와 누적 문장 통계의 읽기는 접속 코드 없이 허용한다. 공개 웹이므로 누구나 주소를 통해 읽을 수 있다. 로그 메모/상태 변경·삭제·인증 발급은 기존 인증을 유지한다. 비밀번호와 로그인 토큰은 기존처럼 제외한다.

재생 검사는 실제 Windows 브라우저 및 Android 크기 Chromium 에뮬레이션으로 구분한다. Windows WebKit에 Web Audio가 없어 iOS 물리 기기 재생 완료로 보고하지 않는다.
