# v0.9.71 검증 기록

## 수정 원인

1. 득점한 카드는 `lastPlayed`/`playedSentences`에 남았지만 클라이언트 `chosen`과 서버 `action`은 손패만 검사했습니다. 화면의 이전 문장을 드래그/클릭하는 동작도 막혀 있었습니다.
2. EXCHANGE 검사/수락은 필드를 지원했지만 `tick` 만료 검사는 손패만 보았습니다. 따라서 필드 카드 요청이 다음 메시지나 타이머에서 취소됐습니다.
3. 제보된 management 예문 두 개는 Kokoro 파일이 없어 기기 TTS로 넘어갔습니다. 실제 로그에서 정확한 문자열과 404 경로를 확인했습니다.

## 변경

- 소유한 손패+필드를 기준으로 제출/작성 순서 검증. 반환은 서버 `recall` 메시지로 소유권·버전·중복 요청을 검사합니다. 기존 점수는 유지합니다.
- 득점한 카드도 드래그/반환/교환 가능. 같은 카드로 이중 득점하지 않도록 이전 지급 그룹과 겹치면 확정 값의 증가분만 지급하며 SQLite 복구에도 보존합니다.
- 교환의 자동 만료 검사에 손패+필드 소유권 적용.
- 제보된 두 문장을 Kokoro af_heart로 실제 생성. 정적 manifest 1,081개. 새 두 MP3 크기/SHA/비무음 검증값은 [JSON](audio-audit/v0.9.71.json)에 있습니다. R2에 새 두 파일을 올렸다는 주장은 하지 않습니다.
- 기본 재생의 기기 TTS 전환과 무음 SpeechSynthesis 프라이머 제거. 음원 누락은 로그에 남고 패널은 자동 종료합니다.
- 대전 예문은 조작 버튼 없이 자동 읽고 종료 2초 후 사라집니다. 실패/차단 시에도 자동으로 사라집니다.

## 실행한 검증

- 단위/실시간 테스트 151개 통과. 신규 회귀: Go 이후 재제출/반환/재사용 중복 득점/복구/교환 타이머/잘못된 반환 검증.
- 최종 Chromium 브라우저 9개 통과: 두 브라우저 세션이 실제 로컬 WebSocket 서버에 연결하여 Go→반환→드래그→모두 반환→재제출→필드 카드 교환 수락. PC와 모바일 크기, 모바일은 작은 visualViewport(330 높이/18 상단 offset)와 CDP 터치 드래그 사용.
- 위 득점 시나리오는 고정 26점 카드 fixture입니다. 정상 덱에서 우연히 그 패를 뽑은 것으로 보고하지 않습니다. 점수를 직접 바꾸는 대신 실제 제출/서버 판정을 실행했습니다.
- Cloudflare 실행 환경 검사는 4개 실제 WebSocket과 자연 지급 덱으로 배분/중복/버리기/SQLite 재시작/전원동의/포기/재대결/origin 거절 통과. 강제 점수/손패/승패를 사용하지 않았습니다.
- 정상 음성/재생 차단/느린 음원/404 조건의 모바일 패널 수명 테스트 4개 통과. 파일 종료 후 2초 자동 닫힘과 실패 시 자동 닫힘, 카드 입력 비차단 검사.
- WebKit의 PC/모바일 크기 Go 편집·교환 2개 통과. Windows WebKit은 실제 iPhone 음성 출력 검증이 아닙니다.
- TypeScript, Vite 빌드, Cloudflare 검사 통과. 실제 Android/iPhone 스피커는 이 PC에서 검증하지 못했습니다.

운영 음원 재생·Netlify 상태는 배포 후 추가 확인합니다. 모든 가능한 품사 배열이나 모든 음원의 발음 품질을 전수 확인했다는 의미는 아닙니다.
