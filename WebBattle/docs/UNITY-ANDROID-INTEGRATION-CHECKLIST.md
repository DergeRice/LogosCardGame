# Unity + 웹뷰 Android 앱 재사용 점검표

이 문서는 로고스 카드게임에서 겪은 홈 이미지 누락, 연출 생략, 낮은 프레임, Google 로그인 창 미표시, 광고·인앱결제 연결 문제를 다른 프로젝트에서 반복하지 않기 위한 기록이다.

## 1. 웹 리소스와 연출

- 앱이 여는 URL과 웹 배포 URL·버전을 확인한다. 브라우저에서 최신 버전이 보인다는 사실만으로 WebView가 같은 파일을 보는 것은 아니다. WebView 캐시, 서비스 워커, `base` 경로, MIME 유형, HTTPS 요청 실패를 기기 로그로 확인한다.
- 이미지와 애니메이션을 첫 화면에서 확인한다. 홈 대표 이미지, 카드·상자 이미지, 모달 전환, Pixi·Canvas 연출을 각각 스크린샷과 화면 녹화로 비교한다. 3초 뒤 fallback이 표시되는 연출은 최초 GPU/WebGL 실패인지, 의도된 접근성 설정인지 구분한다.
- 기기의 `prefers-reduced-motion`, 배터리 절약, WebGL 지원, GPU 가속, 화면 재개 상태를 기록한다. 애니메이션이 빠졌다고 곧바로 웹 리소스 누락으로 판단하지 않는다.
- 콘텐츠 다운로드에 실패해도 빈 화면 대신 이미지 fallback과 오류 메시지를 보여준다. 필수 이미지 파일은 배포 `dist`에 실제 포함되었는지 검사한다.

## 2. 프레임 속도와 Unity 화면

- Unity `Application.targetFrameRate`와 `QualitySettings.vSyncCount`를 먼저 확인한다. 이 프로젝트는 Unity 표면이 5Hz를 요청한 보고가 있었고, 코드에서 15fps 제한도 발견해 60fps로 변경했다. WebView를 Unity `SurfaceView` 위에 합성하는 기기에서는 Unity 프레임 제한이 웹 화면 갱신에도 영향을 줄 수 있다.
- `adb shell dumpsys gfxinfo <패키지> reset` 후 홈 화면에서 30초 이상 측정한다. 시작·광고 전환 중 janky frame 수치와 안정 상태를 분리한다. Chrome에서 같은 웹 URL도 재생하여 앱과 비교한다. Android `gfxinfo`는 WebView/UI 프레임 지표이므로 Unity `SurfaceView` 자체의 FPS라고 단정하지 않는다.
- Unity 카메라의 clear flags를 `SolidColor`, 배경을 흰색으로 설정하고 `RenderSettings.skybox`를 비운다. WebView가 늦게 생성되거나 잠시 숨겨져도 스카이박스가 노출되지 않게 한다.
- 웹뷰 표시 중 Unity 장면의 불필요한 카메라·애니메이션·렌더 루프 부하를 줄인다. 로고스의 변경 후 홈 안정 상태에서 15초 동안 `gfxinfo` 908프레임, janky 0프레임을 측정했다. 광고 전환 중 수치는 별도로 계측한다.

## 3. Google 로그인

- 브라우저용 웹 OAuth 클라이언트와 Android 앱용 OAuth 클라이언트를 구분한다. Android 클라이언트는 **패키지 이름과 실제 설치 앱 서명 SHA-1**이 한 쌍이다. 로컬 `.dev` APK와 Play 설치 운영 APK에는 각각 별도 Android OAuth 클라이언트를 등록한다.
- Play 설치 앱의 SHA-1은 업로드 AAB 인증서가 아니라 Play 앱 서명 인증서에서 확인한다. 서명이 다른 APK를 덮어 설치해 시험하지 않는다.
- Unity WebView에서 웹 브라우저용 Google 팝업을 그대로 열지 말고 Android Credential Manager를 통해 계정을 선택한 뒤, 서버용 웹 클라이언트 ID로 받은 ID 토큰을 서버에 검증시킨다. 로그인 실패·취소·토큰 누락은 UI에 명확히 표시한다.
- 계정 선택과 최초 동의에는 30초 이상 걸릴 수 있다. WebView와 Unity 사이 요청 제한 시간을 로그인 흐름에 맞게 5분으로 잡고, 늦게 도착한 인증 결과가 버려지는지 확인한다. 로고스 개발 APK에서는 동의 화면까지 열린 뒤 기존 30초 제한으로 `Native request timed out`가 표시되어 수정했다.
- 기기에서 로그인 버튼을 실제 눌러 계정 선택창, 앱 복귀, 서버 세션 생성을 확인한다. OAuth 클라이언트 생성만으로 동작 완료로 기록하지 않는다.

## 4. Google Play 인앱결제

- Play Console에서 패키지와 일치하는 일회성 상품을 활성화하고 구매 옵션 ID, 국가별 가격, 라이선스 테스터를 확인한다. 로고스 상품은 `diamonds_100`, `diamonds_300`, `diamonds_1000`, `diamonds_3000`이며 모두 `standard` 옵션이다.
- Billing Client는 실제 `offerToken`으로 결제창을 열고 로그인 계정의 안정적인 해시를 `obfuscatedAccountId`로 넣는다. 상품과 계정이 바뀐 구매 토큰은 거절한다.
- 클라이언트의 성공 응답만으로 재화를 지급하지 않는다. 서버가 Play Developer API의 구매 상태·완료 시각·상품·수량·계정 해시를 검증하고, 토큰 중복 기록과 지급을 하나의 트랜잭션으로 확정한 다음 소비 처리한다. 실패한 소비 처리는 재시도한다.
- 운영 상품의 결제창은 Play에서 배포·설치된 **운영 패키지**로 시험한다. `.dev` 패키지 APK에서 상품 조회가 실패해도 운영 상품 설정이 잘못됐다는 증거는 아니다.
- Play에 올리기 전 AAB 매니페스트의 `versionCode`, `minSdkVersion`, `targetSdkVersion`을 실제로 확인한다. 로고스는 API 34 빌드가 Play 검증에서 막혔고, 최소 API 28은 이전 버전이 지원하던 기기 1,002대를 제외했다. 내부 테스트용 재빌드는 버전 코드 13, 최소 API 25, 대상 API 36으로 맞췄다.
- 업로드 키, Play 앱 서명 키, 로컬 테스트 키는 다를 수 있다. 기존 내부 테스트 AAB의 업로드 인증서와 새 AAB 인증서가 다르면 Play가 업데이트를 거절한다. 키 비밀번호를 잃었다면 Play 업로드 키 재설정 절차를 사용한다.

## 5. 보상형 광고

- LevelPlay 앱 키·광고 단위·placement가 같은 앱에 속하는지 확인한다. SDK 초기화, 광고 로드, 광고 시작, 보상, 닫힘, S2S 콜백을 별도로 기록한다.
- 광고 보상은 클라이언트 콜백이 아니라 서버가 서명 검증한 S2S 콜백으로 지급한다. LevelPlay의 `userId`는 서명에 포함되고 `SetDynamicUserId` 값은 `dynamicUserId`로 별도 전달된다. 광고별 ticket은 1~64자 영숫자로 만들고 계정·상자·거래 ID와 묶는다. 중복 콜백을 거부한다.
- 재생형 광고는 몇 분 걸릴 수 있다. 웹뷰의 네이티브 요청 제한 시간을 광고 길이보다 충분히 길게 잡고, 광고를 일찍 닫으면 지급하지 않는다. 광고가 화면에 떴다는 사실은 보상 지급 검증과 다르다.

## 6. 기기 검증 순서

1. 원본 Unity 프로젝트에서 개발 APK를 빌드해 설치한다. 기기 USB 디버깅·ADB 연결과 정확한 패키지를 확인한다.
2. 홈 이미지, 애니메이션, 상점, 로그인 창, 광고 로드·재생을 눈으로 확인한다. 각 상태의 스크린샷과 `adb logcat` 오류를 보관한다.
3. 홈 안정 상태와 전환 중의 프레임 지표를 따로 측정한다. Unity 프레임 제한·화면 주사율 요청·WebView jank를 각각 본다.
4. 기존 업로드 인증서로 서명한 운영 AAB를 Play 내부 테스트에 배포하고 Play에서 설치한다. 이 앱에서 Google 로그인과 상품 결제창을 시험한다.
5. 테스트 구매 완료·취소·재설치 복구·중복 토큰, 광고 완료·취소·S2S 재전송을 확인한 뒤 운영에 배포한다.

## 이 프로젝트의 2026-10-23 상태

- 홈·상점 이미지가 개발 APK에서 표시된다. Unity 프레임 제한은 60fps, 카메라 배경은 흰색으로 수정했다. 홈 안정 상태 15초 측정값은 908프레임(약 60.5fps), janky 0프레임이다.
- 광고 SDK 초기화·준비·실제 광고 재생과 앱의 보상 완료 이벤트는 Samsung SM-N981N에서 확인했다. S2S 지급은 아직 확인되지 않았다. 서버에서 `dynamicUserId` ticket을 읽도록 수정했다.
- 결제 상품 4개 활성 상태, 서버 검증·중복 방지·지급·소비 코드 및 Cloudflare 배포를 확인했다. Codex가 생성한 기존 업로드 키와 Git에서 제외된 비밀번호 파일을 원본 프로젝트에서 찾았고, 기존 AAB와 인증서가 일치함을 검증했다. Play 설치 운영 앱 결제는 아직 실측 전이다.
- 개발 APK에서 Google 계정 선택창과 최초 동의 화면이 열리는 것을 확인했다. 이 과정에서 30초 제한이 먼저 만료되어 로그인 요청 제한을 5분으로 늘렸다. 새 개발 APK를 Samsung SM-N981N에 설치해 같은 Google 계정 선택 후 로그인된 홈 화면으로 돌아오는 것도 확인했다. 운영 앱용 Android OAuth 클라이언트는 Play 앱 서명 SHA-1로 등록했으며, Play 설치 앱의 로그인 실측은 아직 필요하다.
- 이후 홈 계측에서는 약 27.8초에 1,524프레임이 기록됐지만 janky frame 비율이 99%로 높았다. 앞선 안정 상태 측정과 조건이 달라 원인을 확정하지 않았으며, 실제 화면이 매끄럽다고 판정할 수 없다. 동일한 홈 안정 조건에서 Unity 표면과 WebView/UI 지표를 따로 재측정해야 한다.
