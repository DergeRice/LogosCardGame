# 점수 계산 연출

- 서버 문법 판정의 `usedStartIndex` / `usedLength`에 해당하는 카드만 왼쪽부터 +1로 계산합니다. 인정 구간 밖 카드는 흐려지거나 계산되지 않습니다.
- 기본값은 초록, 곱셈은 보라, 덧셈은 주황, 고 배율은 분홍입니다.
- 카드 수 → 인쇄 곱셈(왼쪽부터) → 인쇄 덧셈(왼쪽부터) → 고 배율 순서를 유지합니다. 좌우 배치로 연산 우선순위가 바뀌지 않습니다.
- 서버 응답 전에는 성공 연출을 시작하지 않습니다. 자기 제출 당시 카드 스냅샷을 보관하여 사용 확정 후에도 계산 중에는 원본 카드와 +1 배지를 보여줍니다. 이것은 시각적 잔상이며 사용한 카드는 서버/손패로 돌아오지 않습니다.
- 계산이 완료되면 점수판을 서버가 확정한 점수까지 정수로 증가시킵니다. 상대 점수와 최고점도 정수 카운터를 사용합니다.
- 20점 이하도 문장 총점은 계산하지만 점수판에는 적립되지 않으며 필드를 유지합니다.
- 고/스톱 선택창은 계산과 점수판 연출 뒤 표시합니다. 서버의 선택 마감시각은 그대로입니다. 최장 약 3.2초이며 ‘계산 건너뛰기’로 즉시 종료할 수 있습니다.
- 재접속으로 받은 과거 판정은 다시 연출하지 않습니다. 새 경기에서는 카운터를 초기화합니다. 운영체제의 동작 줄이기 설정을 존중합니다.

## 디렉팅

- `src/scoreAnimation.ts`의 SCORE_MOTION: 카드 단계 속도, 전체 계산 상한, 숫자 증가 시간, 종료 후 표시 시간.
- `src/score-presentation.css`의 --score-base / --score-multiply / --score-add / --score-go: 색상.
- 같은 파일의 --score-card-opacity: 계산된 카드의 투명도(+1 숫자는 선명하게 유지).

## 검증 구분

- `tests/browser/score-animation.spec.ts`: 서버 응답을 고정한 **UI fixture 검사**. 5×2×2+3+3=26점의 카드 순서, 인정 구간 제외, 단계별 색상, 점수판 중간 정수, 사용 카드 잔상을 PC/모바일에서 검사합니다. 일반 플레이에서 26점 문장을 만든 검사로 보고하지 않습니다.
- `tests/browser/quick.spec.ts`의 두 독립 브라우저 시나리오: 실제 Cloudflare 서버와 자연 지급 손패를 사용하여 제출·정답 유지·새로고침과 카드 조작을 검사합니다. Vite 개발용 HMR 소켓은 대전 서버 주소 검증에서 제외합니다.

## 중앙 순차 계산 표시

계산 패널은 카드 조합 영역 위에 놓습니다. 가운데에 현재 +1/곱셈/덧셈/고 배율 항목 하나만 표시하며, 아래 총점이 정수로 증가합니다. 이전/미래 항목을 목록으로 나열하지 않습니다. PC·모바일 UI fixture 2개 통과(11.1초): 단일 항목 유지, 전체 단계 순서, 단계별 색상, 카드 영역 위/중앙 좌표, 중간 정수 검사. 서버 규칙 변경 없음. Netlify 배포 6ab91ed46a912066b59fa48f 및 공개 빌드 일치 확인.

## 고정된 게이지/계산 행

계산 연출과 오른쪽 덱 게이지를 동일한 108px 높이 HUD 행에 배치했습니다. 계산 패널 및 계산 후 판정 문구는 이 행의 중앙 슬롯을 사용합니다. 별도 행을 삽입하지 않으며 긴 판정 내용은 슬롯 안에서 스크롤합니다. PC/모바일 UI fixture 2개 통과(11.1초): 제출 전·계산 중·연출 제거 후 문장 영역의 문서상 top 좌표가 동일하고, 덱 게이지가 같은 행에 정렬되는지 검사했습니다. 빌드 통과.
